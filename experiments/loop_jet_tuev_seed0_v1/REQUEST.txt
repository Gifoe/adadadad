# 8. Loop-JET 的核心结构

原始：

```text
PatchEmbed

B1
B2
B3
B4
B5
B6
B7
B8
B9
B10
B11
B12

FinalLayer
```

修改为：

```text
PatchEmbed

B1
B2
B3
B4

B5
B6
B7
B8       ← Loop 1

B5
B6
B7
B8       ← Loop 2，完全相同权重

B9
B10
B11
B12

FinalLayer
```

必须保证：

```text
Loop 1 与 Loop 2 完全共享参数。
```

禁止 deepcopy 第二份 blocks。

也就是说：

```python
h = pre_blocks(h, cond)

h1 = loop_blocks(h, cond)

h2 = loop_blocks(h1, cond)

out = post_blocks(h2, cond)
out = final_layer(out, cond)
```

Loop 1 和 Loop 2 使用相同：

```text
flow time t
class condition c
AdaLN conditioning
```

第一轮不要加入：

- loop-index embedding
- computational-time embedding
- XSA
- gated update
- adaptive halting
- K=3
- K=4
- new attention module

本轮只测试最干净的 shared recurrence。


3. load 到 Loop-JET K=1
4. eval mode
5. 输入完全相同 tensor、t、label
6. 比较最终输出

要求：

```text

```

接近数值精度范围。

如果 K=1 无法复现原始 JET forward，不得启动长训练。

同时确认：

```text
Naive Loop K=2 parameter count
```

与原始 JET基本一致。

增加 loop 不应该增加 B5–B8 的参数量。

# 10. Naive Loop-JET K=2

结构：

```text
Pre
→ Loop 1
→ Loop 2
→ Post
→ Final
```

只有最后一次 Loop 输出参与训练 loss。

即：

```text
h1 = F_loop(h0)
h2 = F_loop(h1)

v2 = decoder(h2)

xhat1_2 = x_t + (1-t) * v2
```

训练 objective：

```text
L_naive = original_JET_loss(xhat1_2, x1)
```

必须尽可能原样复用 JET 原来的：

- reconstruction loss
- consistency loss
- geometry/correlation loss
- TV 等组成

不要重新设计 loss。

---

# 11. DS Loop-JET K=2

结构和 Naive 完全相同。

参数也应完全相同。

区别只在训练 supervision。

首先：

```text
h1 = F_loop(h0)
h2 = F_loop(h1)
```

Loop 1 intermediate prediction 必须通过与最终 prediction 相同的 post blocks + final layer：

```text
v1 = Final(Post(h1))
v2 = Final(Post(h2))
```

这里：

```text
Post blocks
Final layer
```

必须共享同一套权重。

不要创建新的 intermediate decoder 参数。

因此：

```text
xhat1_1 = x_t + (1-t) * v1
xhat1_2 = x_t + (1-t) * v2
```

分别计算原始 JET loss：

```text
L1 = JET_loss(xhat1_1, x1)
L2 = JET_loss(xhat1_2, x1)
```

使用：

```text
lambda = 1/3
```

训练 loss：

```text
L_DS = (L2 + (1/3) * L1) / (1 + 1/3)
```

归一化是为了避免简单因为多一个 loss 而明显改变 gradient scale。

注意：

最终 inference 永远使用：

```text
Loop 2
```

绝不能针对 test sample 根据 ground truth 选择 Loop 1 或 Loop 2。

不存在 oracle best-loop selection。

# 14. Early stopping：不要使用 JET 原来的 train-loss early stop

本实验必须使用真正的 validation-based early stopping。

统一监控：

```text
final-loop validation JET loss
```

即：

```text
val_final_loss =
JET_loss(xhat1_2, x1)
```

Naive 和 DS 必须监控完全相同的 metric。

不要用：

```text
DS total training loss
```

做 model selection。

配置：

```text
max_epochs = 200
min_epochs = 60
validation_frequency = every 5 epochs
patience = 6 validation evaluations
```

即：

```text
30 epochs patience
```

relative min improvement：

```text
0.2%
```

定义：

如果：

```text
current_val < best_val * (1 - 0.002)
```

才算新的有效 improvement。

否则 bad_eval_count += 1。

当：

```text
epoch >= 60
```

且：

```text
bad_eval_count >= 6
```

则 early stop。

始终保存：

```text
best_val_checkpoint.pt
```

最后测试使用 best validation checkpoint，而不是最后一个 epoch。

# 15. Validation stochasticity 必须固定

JET 训练涉及随机：

```text
x0 ~ N(0,I)
t ~ p(t)
```

训练阶段继续随机。

但是 validation 不允许每次重新随机，从而让 early stopping 被 Monte-Carlo noise 干扰。

固定：

```text
validation_seed = 20261005
```

针对每个 validation sample，固定其：

```text
x0
t
```

不一定需要把全部 x0 tensor 写到磁盘。

可以通过：

```text
sample index + fixed validation seed
```

确定性重新生成。

要求每次 validation：

同一个 sample 获得同一个 x0 和 t。

Test trajectory audit 同样使用固定 seed。

# 16. 我们真正关心的 Loop 指标

对 validation/test sample，同时获得：

```text
xhat1_1
xhat1_2
x1
```

定义每个样本：

```text
E1 = mean(abs(x1 - xhat1_1))
E2 = mean(abs(x1 - xhat1_2))
```

记录：

```text
mean E1
mean E2
median E1
median E2
```

核心指标 1：

```text
P(E2 < E1)
```

也就是：

```text
fraction of samples improved by Loop 2
```

# 17. Residual-update alignment

这是本轮最关键的机制指标。

定义：

```text
e1 = x1 - xhat1_1
```

第一次 loop 后剩余的 target residual。

第二次 loop 做出的 update：

```text
delta1 = xhat1_2 - xhat1_1
```

将每个 sample 的：

```text
[channel, time]
```

flatten 成向量。

计算：

```text
cosine(delta1, e1)
```

即：

```text
A = <delta1,e1> /
    (||delta1|| * ||e1|| + eps)
```

逐样本计算。

报告：

```text
mean residual cosine
median residual cosine
fraction cosine > 0
fraction cosine > 0.2
```

解释：

```text
cosine > 0
```

说明 Loop 2 update 平均朝向 Loop 1 剩余真实误差。

如果大多数样本明显 > 0：

这是 iterative error correction 的直接证据。

---

# 18. Contraction ratio

定义：

```text
r = E2 / (E1 + eps)
```

报告：

```text
mean r
median r
P(r < 1)
P(r < 0.9)
```

解释：

```text
r < 1
```

代表第二轮 loop 进一步接近 target。

最理想结果：

```text
median r < 1
P(r < 1) clearly > 0.5
residual cosine clearly > 0
```

# 27. 第一轮结果判断标准

第一轮最重要的不是 TS-FID 是否立即 SOTA。

重点依次判断：

## Case A：真正 progressive correction

如果：

```text
E2 < E1 on clear majority of held-out samples
residual cosine > 0
median contraction ratio < 1
```

并且 DS 比 Naive 更明显：

结论：

```text
shared recurrent computation learns an error-correcting refinement process,
and intermediate supervision strengthens that process.
```

这条线值得继续。

---

## Case B：最终变好，但 residual alignment 不明显

如果：

```text
final metrics improve
```

但是：

```text
cos(delta1,e1) ≈ 0
```

说明 loop 更可能只是增加 effective depth，而没有明确形成 target-directed iterative correction。

这仍然可以继续，但 mechanism claim 必须降低。

---

## Case C：Loop 2 经常变差

如果：

```text
E2 > E1
r > 1
```

在大量样本出现：

说明存在 destructive recurrent rewriting / over-refinement。

这将成为下一轮引入：

```text
deep supervision
gating
XSA
loop-time conditioning
```

等机制的依据。

如果 DS 明显缓解这种现象，也要重点报告。

---

## Case D：Loop 1 ≈ Loop 2

如果：

```text
delta1 ≈ 0
E1 ≈ E2
```

说明 recurrent operator 很快进入近似 fixed point，额外 computation 基本冗余。

同样不要自动继续增加 K。
